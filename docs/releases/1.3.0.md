# NavaTunnel 1.3.0

One foreign server can now serve several independent Iran connections with the existing GRE/FRP stack. Service ports, and control ports on different Iran servers, may be identical. Each foreign connection has separate GRE, FRPC, token, traffic counter and selected management controls. Existing first-client names and files are preserved.

Update on Iran and foreign, then reopen the menu:

```bash
NavaTunnel update-all
NavaTunnel
```

Create the tunnel on each Iran and apply each connection code on the same foreign server. On foreign use **1 → 3** to select the Iran connection. New Iran menu allocations reduce GRE-address overlap; foreign rejects any remaining conflict. For older Iran tunnels with the same internal pair, select the second Iran tunnel and use **16** to allocate a new pair and print its replacement command. The first Iran connection is preserved.

Management, watchdog recovery, backup/restore and migration handle the separate clients. `foreign-list` lists IDs; `foreign --foreign-id N` targets status, lifecycle, logs, token, Iran IP, carrier or removal. `--force` updates a matching connection, while `--foreign-id N --force` explicitly selects an existing one.

The WSS TLS helper is unchanged and remains pinned to its verified 1.2.0 binary release. This release updates the Bash management scripts and does not need a new TLS binary.

Validation includes regression tests and a real isolated two-Iran/one-foreign GRE/FOU lab with FRP TCP/UDP forwarding on shared ports, independent counters, and preservation of the second connection during edits, stops and removal of the first.
