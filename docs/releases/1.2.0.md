# NavaTunnel 1.2.0

This release removes Cluster and NavaLink from the menus, supported CLI, provisioning code and runtime. The project name is simply **NavaTunnel**. The English and Persian READMEs and guides now describe the remaining GRE/FRP workflows, with matching menu paths and copyable commands.

## Update

Run on Iran and each foreign endpoint:

```bash
NavaTunnel update-all
NavaTunnel
```

The second command loads the updated menu and runs retirement. Ordinary GRE/FRP configuration, quotas and saved usage are preserved. Removed feature settings are privately archived. Converted NavaLink connections revert to their saved GRE files; update both ends to complete this. Standalone NavaLink connections are stopped and archived because they have no prior GRE counterpart. Conflicts or missing rollback files are reported instead of overwriting working tunnels. See the [operations guide](https://github.com/admin6501/NavaTunnel/blob/main/docs/OPERATIONS.md#upgrading-from-older-versions).

FRP protocols remain available, including WSS. The optional binary now contains only its small TLS front, with no daemon, Cluster routing, SSH provisioning or management API. TLS assets are provided for Linux amd64, arm64, armv7 and 386 with checksums. A normal TCP installation does not need this binary.

Fresh install:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/admin6501/NavaTunnel/main/install.sh)
```

Validation covers shell syntax, English menus, tunnel lifecycle, protocol/port/IP edits, quotas, encrypted backup validation, SSH migration, scoped firewall/SSH retirement, GRE rollback and race-enabled bidirectional TLS forwarding.
