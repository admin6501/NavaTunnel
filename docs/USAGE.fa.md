# راهنمای استفاده از NavaTunnel

[English](USAGE.md) · [صفحه اصلی](../README.fa.md) · [نگهداری](OPERATIONS.fa.md) · [دستورها](CLI.fa.md) · [پرسش‌ها](FAQ.fa.md)

## قبل از شروع

IP عمومی هر دو سرور و پورت اینباندهای موجود روی خارج را آماده کن. مثلاً اگر اینباند خارج روی `8443` گوش می‌دهد، همان پورت را در فهرست سرویس‌ها وارد کن. پورت سرویس برای اتصال کاربر است؛ پورت کنترل برای ارتباط FRPC و FRPS است و باید متفاوت باشد. آدرس‌های داخلی GRE خودکار انتخاب می‌شوند.

NavaTunnel را با [دستور نصب](../README.fa.md#نصب) روی هر دو سرور نصب کن. دستورهای مدیریت به دسترسی root نیاز دارند.

## روی ایران

دستور `NavaTunnel` را اجرا کن و وارد **۱ ← ۱** شو:

1. نام تونل را بنویس؛ Enter یعنی نام خودکار و نام `0` یعنی لغو.
2. IP عمومی ایران را تأیید و IP عمومی خارج را وارد کن.
3. پورت‌های سرویس را با کاما وارد کن. این پورت‌ها روی ایران نباید درگیر برنامه یا تونل دیگری باشند.
4. برای شروع با TCP، به جبران افت بسته `n` جواب بده. پاسخ `y` پروتکل KCP/FEC را انتخاب می‌کند.
5. پورت کنترل آزاد بنویس یا برای انتخاب خودکار Enter بزن.

بعد از ساخت موفق، وارد **۱ ← ۳** شو، تونل را انتخاب کن و **گزینه ۸** را بزن. دستور نمایش‌داده‌شده محرمانه است.

## روی خارج

فقط خطی را اجرا کن که با `NavaTunnel setup-foreign --bundle` شروع می‌شود. متن منو، توضیحات و علامت ترمینال را همراهش کپی نکن. اسکریپت GRE و کلاینت FRPC را تنظیم می‌کند؛ درخواست‌ها به پورت‌های برنامه روی خارج تحویل داده می‌شوند.

برای **ایران جدید**، کد را بدون اضافه‌کردن `--force` اجرا کن. برای **به‌روزرسانی ایران قبلی**، روی خارج همان اتصال را انتخاب کن، گزینه **۶** را بزن و جایگزینی را تأیید کن؛ در خط فرمان، شناسه واقعی خروجی `NavaTunnel foreign-list` را با `--foreign-id N --force` وارد کن. اگر IP ایران عوض شده، انتخاب صریح اتصال قبلی لازم است؛ یکسان‌بودن توکن یا آدرس داخلی به‌تنهایی کافی نیست. قبل از اجرا مطمئن شو کد مربوط به همین خارج است. اگر اتصال دستی متوقف شده، قبل از جایگزینی تنظیمات آن را شروع کن.

بعد از گزارش موفق، برنامه را از طریق IP ایران و پورت فورواردشده امتحان کن. تنظیمات احراز هویت و TLS برنامه باید همچنان با اینباند خارج مطابق باشند.

## مدیریت هر تونل روی ایران

از **۱ ← ۳** تونل را انتخاب کن:

| گزینه | کاربرد |
| --- | --- |
| ۱ / ۲ / ۳ | شروع / توقف / ری‌استارت همین تونل |
| ۴ | تغییر پورت‌های سرویس |
| ۵ | تغییر نام |
| ۶ | تغییر IP خارج |
| ۷ | انتخاب GRE مستقیم یا FOU |
| ۸ | نمایش دستور اتصال خارج |
| ۹ | مصرف، سقف، نحوه محاسبه و ریست |
| ۱۰ | فعال یا غیرفعال‌کردن جبران افت |
| ۱۱ | انتخاب پروتکل FRP |
| ۱۲ | تغییر دائمی MTU |
| ۱۳ | تغییر پورت کنترل FRP |
| ۱۴ | حذف همین تونل |
| ۱۵ | مشاهده یا تغییر توکن |
| ۱۶ | تخصیص آدرس داخلی GRE تازه و نمایش کد اتصال جدید |
| ۰ | بازگشت |

تغییر پورت، توکن، IP، روش انتقال یا پروتکل ممکن است به اجرای کد جدید روی خارج نیاز داشته باشد. ذخیره انتخاب روی ایران به معنی اعمال آن روی خارج نیست؛ دو طرف را هماهنگ کن. تغییر نام فقط برچسب محلی را عوض می‌کند.

پروتکل‌های FRP شامل TCP، KCP، QUIC، WebSocket و WSS هستند. جبران افت بسته از KCP/FEC استفاده می‌کند و ترافیک بیشتری مصرف می‌کند؛ افت فیزیکی مسیر را حذف نمی‌کند. WSS به واسط TLS نیاز دارد که اسکریپت آماده‌اش می‌کند. پروتکل FRP با روش انتقال GRE/FOU متفاوت است.

MTU دو طرف همان تونل را یکسان تنظیم کن. عدد بزرگ‌تر لزوماً بهتر نیست و باید با مسیر و سربار کپسوله‌سازی سازگار باشد. مقدار پیش‌فرض `1380` است.

## مدیریت سمت خارج

روی خارج وارد **۱ ← ۳** شو و اتصال ایران موردنظر را انتخاب کن:

| گزینه | کاربرد |
| --- | --- |
| ۱ / ۲ / ۳ | شروع / توقف / ری‌استارت همین اتصال |
| ۴ | نمایش وضعیت سرویس |
| ۵ | مصرف، نحوه محاسبه، سقف و ریست ترافیک |
| ۶ | اعمال کد جایگزین یا انتخاب پروتکل FRP |
| ۷ | تغییر دائمی MTU |
| ۸ | مشاهده یا تغییر توکن |
| ۹ | تغییر IP عمومی ایران مقابل |
| ۱۰ | حذف فقط همین اتصال |
| ۱۱ | تغییر روش GRE/FOU همین اتصال |
| ۱۲ | نمایش لاگ FRPC همین اتصال |
| ۰ | بازگشت |

اگر چند اتصال داری، تغییرات را از صفحه همان اتصال انجام بده. نام‌های قبلی `frpc.toml` و `gre-tunnel` برای اتصال اول حفظ می‌شوند؛ بقیه، سرویس و فایل و رابط جدا دارند. نام واقعی را از وضعیت بگیر و پسوندها را حدس نزن. توقف دستی بعد از ریبوت و ریستور حفظ می‌شود؛ برای ادامه، **Start** را بزن، نه **Restart**. این گزینه‌ها روی همین سرور عمل می‌کنند و سرور مقابل را از راه دور روشن یا خاموش نمی‌کنند.

## افزودن خارج‌های بیشتر

روی ایران برای هر خارج، **۱ ← ۱** را تکرار کن. هر تونل رابط GRE، سرویس FRPS، پورت کنترل و توکن خودش را دارد. محدودیت ثابت پنج خارج وجود ندارد. پورت‌های سرویس تونل‌ها روی یک IP ایران باید متفاوت باشند.

## تغییر IP

**تغییر ایران:** IP جدید باید از قبل روی سرور فعلی یا جایگزین تنظیم شده باشد. روی ایران وارد **۱ ← ۶** شو. سپس روی هر خارج از **۱ ← ۳** اتصال قبلی را انتخاب کن و با **گزینه ۹**، IP ایران مقابل را تغییر بده؛ یا با **گزینه ۶** کد جدیدش را اعمال کن. برای جایگزینی خط فرمان، `--foreign-id N --force` را صریح وارد کن. این گزینه IP کارت شبکه را تغییر نمی‌دهد.

**تغییر خارج:** روی هر ایران مربوط، تونل را انتخاب کن و با **گزینه ۶**، IP خارج جدید را ثبت کن. تنظیمات خارج را روی مقصد ریستور کن؛ یا برای نصب تازه، کد جدید را آنجا اجرا کن. اگر اتصال قبلاً ریستور شده، از منوی همان اتصال به‌روزش کن و نسخه تکراری نساز. برنامه روی خارج هم باید جدا منتقل شود.

برای جابه‌جایی به دستگاه جدید باید فایل‌ها هم منتقل و ریستور شوند. [راهنمای بکاپ و انتقال](OPERATIONS.fa.md) را ببین.

## اتصال چند ایران به یک خارج

مثلاً دو ایران داریم و اینباند برنامه فقط روی یک خارج است:

```text
Iran A service port 443 ── GRE/FRP A ──┐
                                     ├── Same foreign application on 443
Iran B service port 443 ── GRE/FRP B ──┘
```

1. روی هر سه سرور NavaTunnel را به‌روز کن و دوباره منو را باز کن.
2. روی **ایران اول** از **۱ ← ۱** تونل بساز؛ IP همان خارج و پورت‌های برنامه را وارد کن. از **۱ ← ۳ ← انتخاب تونل ← ۸** کد اتصال را بگیر.
3. دستور آن را روی **خارج** اجرا کن.
4. روی **ایران دوم** هم تونل جدا به **همان IP خارج** بساز. پورت‌های سرویس می‌توانند **دقیقاً همان قبلی‌ها** باشند. کد دوم را روی **همان خارج** اجرا کن و `--force` یا شناسه اتصال قبلی به آن اضافه نکن.
5. روی خارج وارد **۱ ← ۳** شو؛ فهرست اتصال‌ها با نام، IP ایران و پورت کنترل نمایش داده می‌شود. اتصال موردنظر را انتخاب کن. **۱ ← ۴** وضعیت همه را نشان می‌دهد.

اضافه‌کردن ایران جدید، فایل و سرویس FRPC و رابط GRE جدا می‌سازد و ایران اول را جایگزین نمی‌کند. پورت کنترل هم می‌تواند روی دو ایران یکسان باشد، چون روی دو سرور مختلف گوش می‌دهد. `--force` اتصال مطابق را به‌روز می‌کند؛ `--foreign-id N` اتصال قبلی موردنظر را صریح مشخص می‌کند. این‌ها اتصال مستقل‌اند؛ تغییر خودکار مسیر یا لودبالانسر نیستند.

**آدرس‌های داخلی GRE روی خارج نباید تکراری باشند.** تونل‌های تازه منوی ایران، آدرس را با توجه به IP عمومی ایران و آدرس‌های اشغال محلی انتخاب می‌کنند. خارج هم تداخل را قبل از جایگزینی اتصال بررسی می‌کند. ممکن است دو ایران قدیمی هر دو `10.200.0.2 / 10.200.0.1` داشته باشند. در این حالت، روی **ایران دوم** تونل را انتخاب کن و **گزینه ۱۶** را بزن تا آدرس تازه بگیرد؛ بعد دستور جدید را روی خارج اجرا کن. برای این کار لازم نیست ایران اول را تغییر بدهی.

دستورهای خط فرمان روی خارج:

```bash
NavaTunnel foreign-list
NavaTunnel foreign --foreign-id 2 status
NavaTunnel foreign --foreign-id 2 stop
NavaTunnel foreign --foreign-id 2 start
NavaTunnel foreign --foreign-id 2 restart
NavaTunnel foreign --foreign-id 2 logs
```

به‌جای `2` شناسه واقعی خروجی `foreign-list` را بگذار. هنگام ساخت می‌توانی `--name LABEL` هم بدهی؛ به‌روزرسانی همان ایران به `--force` نیاز دارد. اگر IP عمومی ایران تغییر کرد، اول اتصال قبلی را در منوی خارج انتخاب کن و سپس کد جدیدش را اعمال کن؛ در خط فرمان `--foreign-id N --force` را صریح وارد کن. یکسان‌بودن توکن و آدرس داخلی به‌تنهایی باعث جایگزینی IP ایران دیگری نمی‌شود. وقتی چند اتصال داری، برای مدیریت از دستورهای دارای شناسه استفاده کن؛ میانبر قدیمی `--foreign` به کلاینت اول اشاره می‌کند.

## افزودن پروتکل برنامه یا اینباند تازه

اول اینباند جدید را در پنل برنامه روی خارج بساز. روی ایران با **گزینه ۴** مدیریت تونل، پورت جدید را به **فهرست کامل پورت‌های قبلی** اضافه کن؛ این گزینه فهرست را جایگزین می‌کند، پس پورت‌های قبلی را هم بنویس. با **گزینه ۸** کد تازه بگیر و روی خارج، از **گزینه ۶** اتصال همان ایران اعمالش کن. برای هر ایرانی که باید اینباند را ارائه کند، این مراحل را تکرار کن. تنظیمات اتصال جدید برنامه را جدا به کاربران بده؛ NavaTunnel کاربر یا اشتراک نمی‌سازد.

تغییر **پروتکل FRP** فقط روش ارتباط FRPC و FRPS را عوض می‌کند؛ نوع اینباند VLESS/VMess/Trojan را تغییر نمی‌دهد. [پرسش‌های رایج](FAQ.fa.md) و [مرجع دستورها](CLI.fa.md) را هم ببین.
