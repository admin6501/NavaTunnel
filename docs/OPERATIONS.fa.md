# نگهداری NavaTunnel

[English](OPERATIONS.md) · [صفحه اصلی](../README.fa.md) · [راهنمای تونل](USAGE.fa.md)

دستورها را با root اجرا کن و قبل از اجرا، مقدارهای نمونه با حروف بزرگ و `ID` را با مشخصات واقعی جایگزین کن.

## ترافیک و سقف

از منوی اصلی **۶** یا گزینه **۹** مدیریت تونل روی ایران استفاده کن. مشخص کن دانلود، آپلود یا هر دو برای سقف حساب شوند. با رسیدن به سقف، ترافیک همان شمارنده مسدود می‌شود. ریست مصرف، مسدودی سقف را هم رفع می‌کند. سقف صفر یعنی نامحدود.

```bash
NavaTunnel traffic list
NavaTunnel traffic status ID
NavaTunnel traffic limit ID 100GB --mode download
NavaTunnel traffic mode ID both
NavaTunnel traffic reset ID
NavaTunnel traffic limit ID 0
```

تنها واحد ورودی و نمایش، GB ده‌دهی است؛ هر GB یک میلیارد بایت است. شمارنده عادی GRE ترافیک IPv4 داخل تونل را اندازه می‌گیرد؛ دیتاسنتر ممکن است سربار، ارسال مجدد و ترافیک‌های دیگر را هم حساب کند. شمارنده بر اساس IP مقابل، همه ترافیک IPv4 بین دو IP را حساب می‌کند، حتی اگر متعلق به برنامه دیگری باشد. شمارنده‌های هم‌پوشان نساز.

پایش هر ۱۰ ثانیه انجام می‌شود. برای تعمیر پایش بدون ریست آمار و سقف‌ها:

```bash
NavaTunnel traffic repair
systemctl status NavaTunnel-traffic.timer --no-pager
journalctl -u NavaTunnel-traffic.service -n 50 --no-pager
```

## تنظیمات شبکه و امنیت

گزینه‌های منوی اصلی **۲**:

- **۱:** بهینه‌سازی شبکه، BBR، بافر TCP و MTU.
- **۲:** GRE مستقیم، FOU و انتخاب خودکار روش انتقال.
- **۳:** محدودیت نرخ SYN پورت‌های سرویس. این محدودیت روی اتصال‌های جدید اثر می‌گذارد؛ عدد بیش از حد پایین می‌تواند به کاربران آسیب بزند. این گزینه تضمین مقابله با DPI یا فیلترینگ نیست.
- **۴:** ترافیک پوششی تصادفی ICMP. بسته اضافی می‌فرستد و مصرف دارد؛ حجم یک تونل پُرمصرف را مخفی نمی‌کند.
- **۵:** واچ‌داگ، تغییر روش انتقال و هشدار اختیاری تلگرام. قبل از فعال‌کردن هشدار، توکن و مقصد را خودت تنظیم کن.
- **۶:** تنظیمات و وضعیت رمزگذاری، فشرده‌سازی و TLS در FRP.
- **۷:** نگهداری حافظه و swap.
- **۸:** بازگرداندن تنظیمات ذخیره‌شده شبکه.

GRE و FOU به‌تنهایی رمزگذاری ندارند. FRP نسخه ۰٫۷۱ به‌صورت پیش‌فرض TLS دارد، ولی رمزگذاری با تأیید هویت گواهی یکسان نیست. تنظیمات واقعی FRPC/FRPS را بررسی کن و در صورت نیاز از TLS برنامه استفاده کن. اسکریپت برای اینباند برنامه گواهی صادر نمی‌کند. جبران افت KCP/FEC و ترافیک پوششی می‌توانند مصرف دیتاسنتر را افزایش دهند.

## بکاپ

از **۳ ← ۵** استفاده کن یا اجرا کن:

```bash
NavaTunnel backup now
NavaTunnel backup status
```

فایل رمزگذاری‌شده در `/var/backups/navatunnel/` با نامی مانند `navatunnel-backup-YYYYMMDD-HHMMSS.enc` ذخیره می‌شود. کلید آن `/etc/gre-panel/backup.key` است. فایل بکاپ و کلید اصلی آن را با هم نگه دار؛ کلید جدید، بکاپ قدیمی را باز نمی‌کند. پیش‌فرض هفت بکاپ باقی می‌ماند؛ گزینه `backup now --keep N` تعداد نگهداری همان اجرا را تغییر می‌دهد.

بکاپ شامل تنظیمات مدیریت‌شده، توکن‌ها، شمارنده‌ها و سرویس‌هاست؛ دیتابیس و کاربران برنامه روی خارج یا فایل اجرایی FRP را شامل نمی‌شود. برای برنامه خودت جداگانه بکاپ بگیر. هسته FRP هنگام ریستور نصب می‌شود.

## ریستور

اول NavaTunnel را روی مقصد نصب کن. بکاپ و کلید اصلی را امن منتقل کن و کلید اصلی را قبل از ریستور در `/etc/gre-panel/backup.key` قرار بده. اگر بکاپ‌های قبلی مقصد را لازم داری، کلید قبلی مقصد را هم جدا نگه دار.

بررسی بکاپ بدون اعمال تغییر:

```bash
NavaTunnel backup restore /var/backups/navatunnel/BACKUP.enc --dry-run
```

ریستور با همان IP:

```bash
NavaTunnel backup restore /var/backups/navatunnel/BACKUP.enc
```

ریستور روی ایران جایگزین با IP جدیدی که از قبل روی سرور تنظیم شده:

```bash
NavaTunnel backup restore /var/backups/navatunnel/BACKUP.enc --local-ip NEW_IRAN_IP
```

ریستور از تنظیمات قبلی نسخه خصوصی می‌گیرد، مسیرهای آرشیو را اعتبارسنجی می‌کند، FRP را نصب می‌کند، فایل‌ها را برمی‌گرداند و پایش ترافیک را تعمیر می‌کند. توقف دستی قبلی تونل‌ها حفظ می‌شود. اگر سرویسی بالا نیامد، خطا را بررسی کن؛ استخراج فایل به‌تنهایی نشانه برقراری ارتباط نیست. پس از تغییر IP ایران، کد جدید هر تونل را روی خارج مربوط به خودش اجرا کن. اگر خارج چند ایران دارد، اول اتصال قبلی را در منوی آن انتخاب کن یا شناسه‌اش را با `--foreign-id N --force` صریح وارد کن. آدرس اتصال کاربران یا DNS هم ممکن است نیاز به تغییر داشته باشد.

## انتقال با SSH

منوی **۳ ← ۸**، IP مقصد، پورت و کاربر SSH، مسیر اختیاری فایل کلید، بکاپ اختیاری و IP عمومی مقصد را می‌پرسد. در قسمت مسیر کلید، رمز SSH ننویس؛ برای استفاده از رمز یا SSH agent آن را خالی بگذار. اگر مقصد اجبار به تغییر رمز در ورود اول دارد، ابتدا با یک SSH عادی و تعاملی رمز را تغییر بده.

مقصد باید systemd، اینترنت برای دانلود وابستگی‌ها و دسترسی root یا کاربر دارای sudo بدون رمز داشته باشد. تنظیمات مقصد پس از تهیه نسخه خصوصی جایگزین می‌شوند. مبدا روشن می‌ماند.

```bash
NavaTunnel migrate --host DESTINATION_IP --local-ip DESTINATION_PUBLIC_IP
```

گزینه‌های اختیاری: `--port 2222`، `--user ubuntu`، `--identity /root/.ssh/id_ed25519` و `--backup /path/to/BACKUP.enc`.

پس از پایان، مسیر فایل دستورهای جدید خارج روی مقصد نمایش داده می‌شود. هر دستور را روی خارج مربوط اجرا و همه تونل‌ها را تست کن؛ سپس مبدا را بازنشسته کن. انتقال تنظیمات، اشتراک/DNS کاربران یا دیتابیس برنامه را خودکار جابه‌جا نمی‌کند.

## عیب‌یابی

از **۳ ← ۱** یا دستور `NavaTunnel status` شروع کن. لاگ‌ها در **۳ ← ۳** یا `NavaTunnel logs` در دسترس‌اند.

```bash
systemctl status frps frpc --no-pager -l
journalctl -u frpc -n 50 --no-pager
```

روی ایران چندتونله، نام سرویس همان تونل را بررسی کن؛ مثلاً ممکن است سرویس آن `frps-2` باشد. برای دیدن تنظیمات رابط اول:

```bash
ip -d tunnel show gre-tunnel
ip -4 addr show dev gre-tunnel
```

آدرس داخلی واقعی طرف مقابل را پینگ کن؛ همیشه `10.10.10.1` نیست و نصب‌های جدید از `10.200.*` هم استفاده می‌کنند. پینگ IP عمومی دقیقاً مسیر ترافیک برنامه را آزمایش نمی‌کند. افت ICMP می‌تواند ناشی از فیلتر یا محدودیت نرخ هم باشد.

خطای `203/EXEC` معمولاً یعنی فایل اجرایی سرویس وجود ندارد یا قابل اجرا نیست. با `NavaTunnel download-cores` نصب FRP را تعمیر کن، لاگ را بررسی کن و سرویس مربوط را ری‌استارت کن. خطای TCP با متن `connection refused` یعنی مقصد اتصال را رد کرده؛ قبل از عوض‌کردن پروتکل، سرویس FRPS و پورت کنترل همان تونل را بررسی کن.

## ارتقا از نسخه‌های قدیمی

```bash
NavaTunnel update-all
NavaTunnel
```

در نسخه ۱٫۲٫۰، کلاستر و NavaLink حذف شده‌اند. منوها، ساخت اتصال، سرویس مرکزی، APIها و کد مسیریابی آن‌ها دیگر ارائه نمی‌شود. تونل‌های معمولی GRE/FRP باقی می‌مانند.

هنگام اجرا، سرویس‌های متعلق به قابلیت‌های حذف‌شده متوقف و فقط قواعد فایروال خودشان پاک می‌شوند. تنظیمات آن‌ها در `/var/backups/navatunnel/removed-features-*` خصوصی بایگانی می‌شود. تنظیمات ابزارهای حذف‌شده قبلی ممکن است زیر `removed-tools-*` بایگانی شوند. قواعد نامرتبط فایروال، کلیدهای root و تنظیمات تونل‌های معمولی حفظ می‌شوند.

اگر NavaLink از تبدیل GRE ساخته شده باشد، فایل‌های قبلی GRE/FRP برمی‌گردند و شمارنده با حفظ مصرف و سقف دوباره به GRE متصل می‌شود. برای تکمیل برگشت، **هر دو طرف را آپدیت کن**؛ توقف دستی قبلی حفظ می‌شود. اتصال NavaLink تازه، GRE قبلی ندارد: متوقف و تنظیمات و مصرف آن بایگانی می‌شود؛ در صورت نیاز باید تونل عادی جدید بسازی. وجود تداخل یا فایل ناقص، خطای روشن می‌دهد و تونل موجود بازنویسی نمی‌شود. بکاپ قدیمی هم هنگام ریستور با همین روش پاک‌سازی می‌شود.

تنها فایل اجرایی اختیاری Go باقی‌مانده، واسط کوچک TLS برای WSS خودِ FRP است؛ کلاستر، موتور SSH، وب‌پنل یا API مدیریتی ندارد. فقط وقتی واسط WSS تنظیم شده باشد، با بررسی checksum دانلود می‌شود. نصب معمولی TCP به آن نیاز ندارد.

## بکاپ و پایش چند اتصال خارج

بکاپ شامل فهرست `foreign.json`، تنظیمات FRPC و GRE هر اتصال، روش انتقال، شمارنده‌ها و توقف‌های دستی است. ریستور همه کلاینت‌ها را با رابط درست خودشان برمی‌گرداند. پس از انتقال خارج به IP جدید، IP خارج را در تونل مربوط روی **هر ایران** اصلاح کن.

واچ‌داگ اتصال‌های ثبت‌شده خارج را جدا بررسی می‌کند؛ در صورت فعال‌بودن ری‌استارت خودکار، فقط همان اتصال خراب را ری‌استارت می‌کند. توقف دستی حفظ می‌شود. این بررسی، سلامت کلی ارتباط است و درصد دقیق افت بسته را اندازه نمی‌گیرد.
