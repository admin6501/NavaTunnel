# NavaTunnel command reference

[فارسی](CLI.fa.md) · [Home](../README.md) · [Setup](USAGE.md) · [Operations](OPERATIONS.md) · [FAQ](FAQ.md)

Run management commands as root. Replace uppercase placeholders before running an example; commands in one block are examples, not a sequence to paste blindly. `NavaTunnel --help` shows the command summary. Use the menu for a first setup; low-level legacy setup commands use fixed default GRE addresses unless you provide different ones.

## Inspect and select

```bash
NavaTunnel
NavaTunnel menu
NavaTunnel peer-list
NavaTunnel foreign-list
NavaTunnel doctor check
NavaTunnel status
```

Iran peer IDs come from `peer-list`; foreign connection IDs come from `foreign-list`. These are different registries. A traffic counter ID comes from `traffic list`; an interface name comes from the selected tunnel's status. Do not assume they share a numeric suffix.

## Connect foreign

For a new Iran connection, use the full private code generated by Iran:

```bash
NavaTunnel setup-foreign --bundle CODE --name Iran-B
```

Update a specific existing connection, including an Iran IP move:

```bash
NavaTunnel setup-foreign --bundle NEW_CODE --foreign-id FOREIGN_ID --force
```

An optional `--frp-transport tcp|kcp|quic|websocket|wss` overrides the code's protocol. `--loss-recovery on|off` selects recovery explicitly; use coordinated Iran settings rather than conflicting overrides. Proxy options include `--frp-encryption on|off` and `--frp-compression on|off`. `--relay-ip IP` changes the application target; enable `--proxy-protocol v1|v2` only if that application explicitly accepts it. The default application target is `127.0.0.1` with proxy protocol off.

`NavaTunnel bundle inspect CODE` decodes a code with the token masked by default. `--show-token`, `peer-token` and token-view commands below expose secrets. Do not hand-edit bundle fields; obtain a new code after changing settings on Iran.

## Manage an Iran peer

```bash
NavaTunnel tunnel-power start --id IRAN_ID
NavaTunnel tunnel-power stop --id IRAN_ID
NavaTunnel edit-peer --id IRAN_ID --name New-name
NavaTunnel edit-peer --id IRAN_ID --ports "443,8443,9443"
NavaTunnel edit-peer --id IRAN_ID --remote-pub NEW_FOREIGN_IP
NavaTunnel edit-peer --id IRAN_ID --carrier fou:55555
NavaTunnel peer-control-port --id IRAN_ID --port auto
NavaTunnel peer-protocol --id IRAN_ID --protocol tcp
NavaTunnel loss-recovery --id IRAN_ID --mode off
NavaTunnel peer-addresses --id IRAN_ID --auto
NavaTunnel peer-token --id IRAN_ID
NavaTunnel connection-token --id IRAN_ID
NavaTunnel connection-token --id IRAN_ID --token NEW_TOKEN
NavaTunnel iran-ip --ip NEW_IRAN_IP
```

`--ports` replaces the entire forwarded-port list. `peer-control-port` also accepts an explicit port number. `peer-addresses` also accepts `--local-gre IRAN_GRE_IP --peer-gre FOREIGN_GRE_IP` for a valid private /30 pair; changing it interrupts the selected path. `iran-ip` changes all registered Iran peers' public endpoint setting, not the OS interface. Reconcile these changes with the matching foreign connection; the printed code is not executed there automatically. For selected Iran restart, use menu **1 → 3 → select → 3**.

## Manage a selected foreign connection

```bash
NavaTunnel foreign --foreign-id FOREIGN_ID status
NavaTunnel foreign --foreign-id FOREIGN_ID start
NavaTunnel foreign --foreign-id FOREIGN_ID stop
NavaTunnel foreign --foreign-id FOREIGN_ID restart
NavaTunnel foreign --foreign-id FOREIGN_ID logs
NavaTunnel foreign --foreign-id FOREIGN_ID token
NavaTunnel foreign --foreign-id FOREIGN_ID token --token NEW_TOKEN
NavaTunnel foreign --foreign-id FOREIGN_ID iran-ip --ip NEW_IRAN_IP
NavaTunnel foreign --foreign-id FOREIGN_ID carrier fou:55555
```

Carrier `direct` is also supported. Keep the matching Iran carrier/token coordinated. Legacy `tunnel-power ... --foreign`, `connection-token --foreign` and `foreign-iran-ip --ip IP` address the original client; use the selected commands when several clients exist. Deletion is covered separately below.

## MTU and traffic

```bash
NavaTunnel mtu --interface GRE_INTERFACE --value 1380
NavaTunnel traffic list
NavaTunnel traffic status COUNTER_ID
NavaTunnel traffic limit COUNTER_ID 100GB --mode download
NavaTunnel traffic mode COUNTER_ID both
NavaTunnel traffic reset COUNTER_ID
NavaTunnel traffic limit COUNTER_ID 0
NavaTunnel traffic repair
```

Set MTU on both ends of the same link. Accepted MTU is 576–1476; the current KCP implementation requires at least 1378, so use a different FRP transport before lowering it below that value. These are validation bounds, not a guarantee that every value fits your path. Usage is decimal GB; reset clears the accumulated usage, not the cap. [Traffic details](OPERATIONS.md#traffic-and-quotas)

Counters are normally registered automatically. Advanced manual counters use `traffic add COUNTER_ID --interface GRE_INTERFACE` or `--peer PEER_PUBLIC_IP`; do not overlap them with existing counters. `traffic discover` finds active managed GRE interfaces and registers missing counters, preserving existing ones; `traffic remove COUNTER_ID` deletes a counter and its enforcement, not the underlying tunnel.

## Host-wide settings and monitoring

```bash
NavaTunnel perf status
NavaTunnel perf enc on
NavaTunnel perf comp off
NavaTunnel perf tls on
NavaTunnel perf apply
NavaTunnel tune-status
NavaTunnel carrier status
NavaTunnel watchdog status
NavaTunnel watchdog check
NavaTunnel watchdog on
NavaTunnel watchdog off
```

`perf apply` applies saved host FRP settings and restarts relevant services; it is not scoped by the selected tunnel menu. `optimize` applies system network tuning; `restore` restores **network tuning**, not an encrypted backup. `free-ram` also changes swap/log settings. Inspect their menu descriptions before applying them. Global `carrier mode direct` or `carrier mode fou:PORT` can change all active GRE interfaces; selected per-connection controls are preferred on a multi-client host. `carrier next` cycles configured candidates; it does not select the best Iran for your users. [Custom chaff/SYN settings and watchdog](OPERATIONS.md#network-and-security-settings)

Telegram is optional: configure credentials and the actual SOCKS5 route if needed through **2 → 5**. `watchdog test` sends a test notification; `tgsend "MESSAGE"` sends a manual message. A forwarded Xray inbound is not automatically a SOCKS proxy. Automatic restart is off in a fresh watchdog configuration; enabling monitoring alone does not enable it.

## Backup, restore and migration

```bash
NavaTunnel backup now --keep 7
NavaTunnel backup status
NavaTunnel backup schedule --every 6
NavaTunnel backup schedule --daily 03:00
NavaTunnel backup schedule --off
NavaTunnel backup restore /path/BACKUP.enc --dry-run
NavaTunnel backup restore /path/BACKUP.enc --local-ip DESTINATION_PUBLIC_IP
NavaTunnel migrate --host SSH_DESTINATION_IP --local-ip DESTINATION_PUBLIC_IP
```

Choose one schedule and ensure the maintenance timer runs. Restore requires the archive's original `/etc/gre-panel/backup.key`. `--local-ip` means the destination's **own** public IP on both Iran and foreign. Migration accepts `--port PORT`, `--user USER`, `--identity KEY_FILE` and `--backup BACKUP_FILE`. Without `--backup`, it makes a fresh encrypted archive. [Role-specific migration and manual transfer](OPERATIONS.md#migrate-over-ssh)

## Diagnose, update and remove

`doctor check` checks registered peers. Legacy `doctor diag` (alias `speed`) uses first-interface discovery, runs ping/MTU/throughput probes and can offer tuning; prefer explicit peer addresses on multi-tunnel hosts. `doctor server` starts iperf3 on port 5201 and `doctor stop-server` stops server processes; this is not a per-connection server manager. Limit access while testing. `stress-test HOST PORT COUNT` generates test connections and does not verify application sessions.

```bash
NavaTunnel logs
NavaTunnel update-all
NavaTunnel download-cores
```

`logs` follows local FRP journals; Ctrl+C exits. `update` and `update-all` update management scripts; `download-cores` installs/repairs executable FRP binaries. Updating the source scripts does not update another endpoint remotely.

To delete one connection, use the selected menu or these commands; `--force` skips their confirmation:

```bash
NavaTunnel remove-peer --id IRAN_ID --force
NavaTunnel foreign --foreign-id FOREIGN_ID remove --force
```

Global `restart` restarts local tunnel services; prefer a selected action when preserving another connection. `remove-tunnel` removes **all** local tunnel components. `uninstall` also removes the management scripts and state, including the backup key. Back up and copy the archive/key off-host before removal. Neither command removes the opposite endpoint or the application database.
