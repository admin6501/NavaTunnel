# NavaTunnel

[English](README.md) | **فارسی**

مدیریت تونل معکوس FRP روی GRE، با توسعه و نگهداری **admin6501**.
منوهای فارسی، مدیریت ترافیک، انتخاب پروتکل، تنظیم MTU، تغییر IP ایران، مستندات و اصلاحات این نسخه در مخزن NavaTunnel توسعه داده شده‌اند.
تمام مدیریت از SSH و منوی فارسی انجام می‌شود. پنل وب، سرور وب، نصب‌کننده پنل و فرایندهای ساخت Go حذف شده‌اند.

حامل GRE می‌تواند مستقیم یا FOU روی UDP باشد. پروتکل اتصال، رمزگذاری و فشرده‌سازی FRP روی کلاینت خارج اعمال می‌شوند؛ منوی ایران انتخاب هر تونل را ذخیره و در کد اتصال منتقل می‌کند. حامل رله وب در این نسخه موجود نیست.

برای تعداد سرورهای خارج سقف ثابت وجود ندارد؛ هر تونل به IP خارج و آدرس داخلی مستقل و پورت‌های کنترل و سرویس آزاد نیاز دارد. در نسخه فعلی، هر سرور خارج یک اتصال FRPC را مدیریت می‌کند.

## نصب و به‌روزرسانی

روی سرور لینوکس دارای systemd، Python 3 و iptables، با دسترسی روت اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/admin6501/NavaTunnel/main/install.sh)
```

برای بازکردن منو `NavaTunnel` و برای راهنمای فارسی فرمان‌ها `NavaTunnel --help` را اجرا کنید. در نسخه محلی از `sudo bash NavaTunnel.sh` استفاده کنید. نصب تونل پیش‌نیازها و فایل‌های اجرایی لازم را دریافت می‌کند. ابزارهای ترافیک و ترافیک پوششی نیز اسکریپت Bash هستند.

برای نسخه جدید، از منوی **به‌روزرسانی و نگهداری → به‌روزرسانی کامل** استفاده کنید یا `NavaTunnel update-all` را اجرا کنید؛ سپس منو را ببندید و دوباره باز کنید. ایران و هر سرور خارج باید جداگانه به‌روز شوند. به‌روزرسانی برای نمایش منوهای جدید نیاز به حذف و ساخت دوباره تونل ندارد.

## مدیریت ساده از منو

با اجرای `NavaTunnel` منوی اصلی باز می‌شود:

1. **ساخت و مدیریت تونل‌ها → ساخت روی ایران**: نام، IP دو سرور و پورت‌های سرویس را وارد کنید. توکن و آدرس‌های داخلی خودکار ساخته می‌شوند؛ پورت کنترل را دستی وارد کنید یا با Enter / `auto` خودکار انتخاب کنید؛ برای سرورهای بیشتر هم همین مسیر را بروید.
2. **انتخاب و مدیریت یک تونل**: تونل را از فهرست شماره‌دار انتخاب کنید؛ سپس فقط مورد دلخواه، مثل نام، پورت یا IP خارج، را تغییر دهید. Enter در فیلد ویرایش یعنی بدون تغییر و گزینه 0 یعنی بازگشت.
3. **کد اتصال خارج**: کد همان تونل را دریافت کنید و روی سرور خارج اجرا کنید؛ یا در منوی خارج، کد را بچسبانید. پس از تغییر پورت‌ها، کد جدید را روی خارج دوباره اعمال کنید. منو پیش از جایگزینی تونل موجود تأیید می‌گیرد.
4. **مصرف ترافیک، سقف و ریست**: تونل را از فهرست انتخاب کنید. عدد `100` در منو یعنی 100GB؛ `0` یعنی نامحدود. دانلود، آپلود یا هر دو را با شماره انتخاب کنید.

هنگام ورود، بازگشت و تازه‌سازی منوها، صفحه ترمینال پاک می‌شود تا فقط صفحه جاری دیده شود. نتیجه عملیات و کد اتصال تا زدن Enter روی صفحه می‌مانند. تغییر IP ایران فقط در منوی سراسری تونل‌ها قرار دارد.

ری‌استارت و حذف در صفحه مدیریت، فقط روی تونل انتخاب‌شده انجام می‌شوند. نصب تک‌تونلی قدیمی ایران، اگر تنظیمات IP و GRE در فایل سرویس قابل تشخیص باشند، خودکار به فهرست اضافه می‌شود. در سرور خارج می‌توانید با کد اتصال جدید، تنظیمات را جایگزین کنید؛ برای مشاهده وضعیت از فهرست و وضعیت تونل‌ها استفاده کنید.

## فهرست و مدیریت روی سرور خارج

در **ساخت و مدیریت تونل‌ها → ۴) فهرست و وضعیت تونل‌ها**، تونل‌های ایران از فایل ثبت peers و اتصال خارج از `frpc.toml` خوانده می‌شوند. اتصال خارج حتی بدون فایل ثبت peers نمایش داده می‌شود: مقصد داخلی ایران، پروتکل FRP، وضعیت سرویس، اینترفیس GRE و پورت‌های TCP/UDP. توکن در فهرست چاپ نمی‌شود. وضعیت فعال سرویس به‌تنهایی تضمین دسترسی به سرور مقابل نیست.

گزینه **۳) انتخاب و مدیریت یک تونل** روی سرور خارج، صفحه مدیریت FRPC را باز می‌کند: نمایش وضعیت، ری‌استارت همین اتصال، ترافیک و تغییر تنظیمات با کد اتصال. اگر هر دو نقش روی یک سرور تنظیم شده باشند، ابتدا نقش ایران یا خارج را انتخاب کنید. نیازی به ساخت مجدد تونل برای اضافه‌شدن آن به فهرست خارج نیست.

## انتخاب پروتکل FRP در منو

روی **سرور ایران**: منوی **ساخت و مدیریت تونل‌ها → انتخاب و مدیریت یک تونل → ۱۰) انتخاب پروتکل FRP** را باز کنید. یکی از `TCP`، `KCP`، `QUIC`، `WebSocket` یا `WSS` را انتخاب کنید. مقدار فعلی بالای منو نمایش داده می‌شود و Enter آن را نگه می‌دارد. این انتخاب در ایران ذخیره می‌شود؛ سپس کد اتصال جدید را از گزینه ۵ بگیرید و روی سرور خارج اعمال کنید.

روی **سرور خارج**: در **ساخت و مدیریت تونل‌ها → اتصال سرور خارج با کد اتصال**، پس از چسباندن کد، همان پنج گزینه نمایش داده می‌شود. Enter، پروتکل ذخیره‌شده در کد را انتخاب می‌کند. همچنین نصب دستی خارج انتخاب پروتکل دارد. اعمال کد جدید بر تونل موجود نیاز به تأیید جایگزینی دارد.

پروتکل اتصال را **کلاینت FRP روی خارج** استفاده می‌کند؛ سرور FRP روی ایران اتصال را می‌پذیرد. انتخاب در منوی ایران به‌تنهایی اتصال فعلی خارج را تغییر نمی‌دهد. تنظیم GRE مستقیم یا FOU همچنان گزینه جداگانه ۴ در مدیریت تونل است.

| گزینه | رفتار |
|---|---|
| TCP | حالت پیش‌فرض با ارسال مجدد TCP |
| KCP | انتقال روی UDP همراه FEC؛ مصرف ترافیک بیشتر |
| QUIC | انتقال روی UDP؛ بدون FEC حالت KCP |
| WebSocket | اتصال FRP روی WebSocket |
| WSS | اتصال WebSocket با TLS |

KCP و جبران افت بسته هماهنگ‌اند: انتخاب KCP گزینه جبران را فعال می‌کند؛ انتخاب پروتکل دیگر آن را غیرفعال می‌کند. فعال‌سازی جبران از گزینه ۹، پروتکل را KCP می‌کند. غیرفعال‌کردن آن، KCP را به TCP برمی‌گرداند؛ اگر پروتکل دیگری انتخاب شده باشد همان باقی می‌ماند.

```bash
NavaTunnel peer-protocol --id 2 --protocol quic
NavaTunnel peer-token --id 2
```

کد جدید را با نسخه جدید NavaTunnel روی خارج اعمال کنید. سرور ایران برای KCP از UDP پورت کنترل و برای QUIC از پورت بعدی آن (در انتهای بازه، پورت قبلی) استفاده می‌کند؛ تنظیمات UFW این پورت‌ها را مجاز می‌کنند، ولی فایروال سفارشی باید جداگانه تنظیم شود. انتخاب یک پروتکل به‌تنهایی تضمین بهبود سرعت یا عبور از محدودیت مسیر نیست.

## جبران افت بسته برای هر تونل

هنگام ساخت تونل، سؤال **آیا می‌خواهید جبران افت پکت فعال شود؟ [y/N]** نمایش داده می‌شود:

- `y`: اتصال FRP آن تونل روی **KCP همراه FEC** تنظیم می‌شود.
- `n` یا Enter: حالت پیش‌فرض TCP باقی می‌ماند و FEC اضافه فعال نمی‌شود؛ TCP همچنان ارسال مجدد معمول خودش را دارد.

برای تونل موجود، از **انتخاب و مدیریت یک تونل → ۹) جبران افت بسته** استفاده کنید. در این بخش گزینه **۱) فعال‌سازی**، **۲) غیرفعال‌سازی** و **۳) نمایش انتخاب ذخیره‌شده** وجود دارد. Enter یا 0 فقط بازمی‌گردد و تنظیم را تغییر نمی‌دهد. انتخاب جداگانه در رکورد همان تونل ذخیره و پس از ذخیره از فایل دوباره خوانده و تأیید می‌شود. بستن منو یا اجرای مجدد اسکریپت انتخاب را پاک نمی‌کند. بعد از هر تغییر، دستور آماده اعمال روی خارج چاپ می‌شود. سپس **کد اتصال خارج** را دریافت و روی سرور خارج دوباره اعمال کنید؛ در منو جایگزینی تنظیمات فعلی را تأیید کنید. ذخیره انتخاب روی ایران به‌تنهایی اتصال فعال خارج را تغییر نمی‌دهد. عنوان وضعیت در ایران «انتخاب ذخیره‌شده ایران» است؛ وضعیت واقعی خارج از روی این فایل قابل تأیید نیست. تغییر مستقیم پروتکل در خارج به‌صورت خودکار در فایل ایران ذخیره نمی‌شود. برای هماهنگی، همان پروتکل را در گزینه ۱۰ ایران انتخاب کنید. وضعیت FEC از پروتکل تعیین می‌شود: KCP فعال است و پروتکل‌های دیگر FEC حالت KCP را ندارند. هر دو سمت باید نسخه جدید NavaTunnel را داشته باشند تا گزینه داخل کد اتصال منتقل شود.

```bash
NavaTunnel loss-recovery --id 2 --mode on
NavaTunnel peer-token --id 2
# اعمال کد اتصال جدید روی خارج:
NavaTunnel setup-foreign --bundle '<bundle>' --force
# تغییر صریح روی خارج:
NavaTunnel setup-foreign --bundle '<bundle>' --loss-recovery off --force
```

`add-peer` و `setup-foreign` نیز گزینه `--loss-recovery on|off` دارند. تنظیم فعال با انتخاب صریح پروتکل دیگری مثل QUIC تعارض دارد و رد می‌شود. کدهای اتصال قدیمی همچنان قابل استفاده‌اند.

FEC می‌تواند بخشی از داده گم‌شده را با بسته‌های افزونه بازیابی کند؛ افت مسیر یا افت بسته‌های سایر ترافیک‌های سرور را حذف نمی‌کند و تضمینی برای افت‌های شدید یا پشت‌سرهم ندارد. در FRP upstream نسخه 0.71.0، KCP از ۱۰ قطعه داده و ۳ قطعه افزونه استفاده می‌کند؛ یعنی در جریان پرحجم تقریباً ۳۰٪ افزونگی در سطح داده کدگذاری‌شده، علاوه بر سربار پروتکل و ارسال مجدد. مقدار نهایی مصرف وابسته به اندازه بسته‌ها و وضعیت مسیر است. این مصرف اضافه از سهمیه ترافیک تونل و دیتاسنتر کم می‌شود. KCP از UDP داخل GRE روی همان شماره پورت کنترل استفاده می‌کند؛ فایروال سفارشی باید این ترافیک را مجاز کند.

## MTU دائمی هر تونل

روی ایران از **مدیریت همان تونل → ۱۱) تغییر دائمی MTU** و روی خارج از **مدیریت اتصال → ۵) تغییر دائمی MTU** استفاده کنید. مقدار فعلی نمایش داده می‌شود؛ Enter یعنی لغو. تغییر فقط روی اینترفیس همان تونل اعمال و در فایل سرویس و `/etc/gre-panel/mtu.json` ذخیره می‌شود. ری‌استارت، تغییر حامل و بهینه‌سازی معمول، مقدار اختصاصی ذخیره‌شده را حفظ می‌کنند. اگر اعمال تغییر ناموفق باشد، تنظیم قبلی بازگردانده می‌شود. قواعد MSS بر اساس MTU مسیر و اینترفیس همان تونل تنظیم می‌شوند.

MTU دو سمت را هماهنگ کنید؛ تغییر روی ایران به‌تنهایی MTU خارج را تغییر نمی‌دهد. مقدار پیش‌فرض 1380 و بازه ورودی 576 تا 1476 است. حداکثر مناسب مسیر ممکن است کمتر باشد؛ کاهش MTU همیشه سرعت را بیشتر نمی‌کند. KCP نسخه فعلی بسته‌های 1350 بایتی می‌فرستد و با سربار IPv4/UDP، MTU داخل GRE باید حداقل 1378 باشد؛ اسکریپت انتخاب KCP با MTU کمتر و کاهش MTU زیر این حد در حالت KCP را رد می‌کند.

نمونه برای تونل دوم روی ایران و تونل متناظر روی خارج، در حالت TCP:

```bash
# روی ایران
NavaTunnel mtu --interface gre-t2 --value 1300
# روی خارج متناظر
NavaTunnel mtu --interface gre-tunnel --value 1300
```

## مصرف ترافیک هر تونل

در صفحه مدیریت هر تونل، دانلود، آپلود، مجموع و مصرف محاسبه‌شده برای سقف نمایش داده می‌شوند. از **گزینه ۷ روی ایران** یا **گزینه ۳ روی خارج** وارد تنظیمات ترافیک همان اتصال شوید؛ نیازی به انتخاب دوباره یا واردکردن شناسه شمارنده نیست. تازه‌سازی، سقف مصرف، نحوه محاسبه، ریست و نامحدودکردن همان‌جا انجام می‌شوند. ریست مصرف نیاز به تأیید دارد.

از **گزینه ۶ منوی اصلی** نیز می‌توانید همه شمارنده‌ها را ببینید، تونل‌های موجود را شناسایی کنید یا اینترفیس و IP اختصاصی ثبت کنید. خروجی‌ها چندخطی و با واحد GB هستند تا در ترمینال باریک خوانا باشند. عدد `100` در منو یعنی 100GB و `0` یعنی نامحدود؛ در منو و CLI فقط `GB` پشتیبانی می‌شود؛ عدد بدون واحد هم GB است. هر GB برابر ۱٬۰۰۰٬۰۰۰٬۰۰۰ بایت است. ورودی GiB و واحدهای دیگر پذیرفته نمی‌شوند. سقف‌های قبلی بر حسب بایت حفظ می‌شوند و فقط نمایش آن‌ها به GB تغییر می‌کند.

تونل‌های تازه به‌صورت خودکار با نام اینترفیس، مثل `gre-tunnel` یا `gre-t2`، ثبت می‌شوند. اگر شمارنده موجود نیست، منو پیش از ثبت سؤال می‌کند و شمارش از همان لحظه آغاز می‌شود. هنگام تازه‌سازی ناموفق، آخرین مصرف ذخیره‌شده همراه پیام خطا نمایش داده می‌شود؛ تاریخچه مصرف دیتاسنتر قابل بازیابی نیست.

```bash
NavaTunnel traffic discover
NavaTunnel traffic list
NavaTunnel traffic limit gre-tunnel 100GB --mode both
NavaTunnel traffic status gre-tunnel
NavaTunnel traffic reset gre-tunnel
NavaTunnel traffic mode gre-tunnel download
NavaTunnel traffic limit gre-tunnel 0  # نامحدود و رفع مسدودی
```

ثبت اینترفیس یا IP اختصاصی:

```bash
NavaTunnel traffic add tunnel-a --interface tun0 --limit 100GB --mode upload
NavaTunnel traffic add frp-a --peer 203.0.113.10 --limit 500GB --mode both
NavaTunnel traffic remove tunnel-a  # حذف شمارنده و رفع مسدودی
```

- **download**: بایت‌های دریافت‌شده توسط همین سرور (RX).
- **upload**: بایت‌های ارسال‌شده توسط همین سرور (TX).
- **both**: مجموع دو جهت.
- شمارنده اینترفیس، ترافیک IPv4 داخل تونل، سرآیند IP و ارتباط‌های نگهداری را می‌شمارد. شمارنده IP مقابل، کل ترافیک IPv4 آن مقصد، سربار و ارتباط‌های دیگر را هم شامل می‌شود؛ از IP اختصاصی استفاده کنید. مقصد تکراری یا هم‌پوشان رد می‌شود.
- هر 10 ثانیه مصرف نمونه‌برداری می‌شود. رسیدن مصرف انتخاب‌شده به سقف، با قواعد اختصاصی iptables هر دو جهت همان تونل را مسدود می‌کند؛ شمارنده و سقف تونل‌های دیگر مستقل می‌مانند.
- ریست، دوره مصرف تازه ایجاد و مسدودی را رفع می‌کند. تغییر نحوه محاسبه، مصرف همان دوره را از RX/TX موجود دوباره محاسبه می‌کند. بالا بردن یا حذف سقف، اگر مصرف از سقف جدید کمتر باشد، تونل را باز می‌کند.
- مصرف و سقف‌ها در `/etc/gre-panel/traffic.json` باقی می‌مانند. سرویس `NavaTunnel-traffic.service` قواعد را پس از راه‌اندازی سیستم بازسازی و زمان‌سنج شمارش را ادامه می‌دهد. راه‌اندازی مجدد یا جایگزینی فایروال ممکن است مصرف از آخرین نمونه را از دست بدهد؛ سقف نیز می‌تواند به اندازه ترافیک یک فاصله نمونه‌برداری تجاوز کند.
- این سقف محلی، معادل صورتحساب دیتاسنتر نیست. IPv6 پشتیبانی نمی‌شود و ترافیک IPv6 داخل اینترفیس‌های TUN سفارشی را پوشش نمی‌دهد.

برای بررسی سرویس شمارنده:

```bash
systemctl status NavaTunnel-traffic.timer NavaTunnel-traffic.service
journalctl -u NavaTunnel-traffic.service
```

## تنظیمات و پشتیبان‌ها

لاگ‌ها در `/var/log/navatunnel` و پشتیبان‌ها در `/var/backups/navatunnel` هستند. سرویس‌های پایش و DPI از پیشوند `navatunnel-` استفاده می‌کنند. هنگام ارتقای نصب قدیمی، سرویس‌های قبلی را متوقف و پشتیبان‌ها یا لاگ‌های موردنیاز را پیش از فعال‌سازی سرویس‌های جدید منتقل کنید؛ پوشه‌ها و سرویس‌های قدیمی خودکار مهاجرت نمی‌کنند.

فایل‌های وضعیت برای سازگاری با نصب موجود در `/etc/gre-panel` باقی می‌مانند؛ این نام به معنی نصب یا اجرای پنل وب نیست. پشتیبان رمزگذاری‌شده از `/etc/gre-panel/backup.key` استفاده می‌کند؛ هنگام انتقال سرور، کلید اصلی را نگه دارید و نسخه بازیابی را خارج از سرور ذخیره کنید.

وضعیت ترافیک و MTU در پشتیبان‌ها موجود است. پس از بازگردانی روی سرور جایگزین، با `NavaTunnel traffic list` سرویس و زمان‌سنج شمارنده را نصب و فعال کنید. پنل وبِ نصب‌شده قبلی خودکار از سرور حذف نمی‌شود؛ پیش از جایگزینی، از آن پشتیبان بگیرید و مهاجرت کنید. حذف کامل شامل پاک‌سازی فایل‌ها و سرویس پنل قدیمی است.

به‌روزرسانی اسکریپت از همین مخزن انجام می‌شود؛ فایل‌های اجرایی FRP از انتشارهای بالادستی و نشانی‌های جایگزین دریافت می‌شوند. همه متن‌های خود اسکریپت، منوها، خطاها، نصب‌کننده و راهنما فارسی‌اند؛ نام فرمان‌ها، کلیدهای تنظیمات، پروتکل‌ها و خروجی خام ابزارهای خارجی مثل FRP و systemd نام فنی اصلی خود را دارند.

## بررسی و تست

```bash
for script in *.sh; do bash -n "$script"; done
python3 -m unittest discover -s tests -v
```

تست‌ها تخصیص شناسه بدون سقف ثابت، ساخت کد اتصال، حذف مستقل تونل‌ها، ویرایش TOML، تداخل پورت، ورودی ناقص، فرمان‌های حامل و شکست نصب یا پشتیبان را پوشش می‌دهند. تست‌های ترافیک، شمارنده فایروال را شبیه‌سازی و محاسبه دو جهت، ریست، سقف مستقل، ماندگاری و رفع مسدودی را بررسی می‌کنند. تست‌های مدیریت، انتخاب صحیح تونل، پروتکل و جبران افت بسته، نمایش خارج، ذخیره و بازگردانی MTU، جداسازی مصرف و فارسی‌بودن راهنما را بررسی می‌کنند.

تست واقعی شبکه و systemd نیاز به سرور لینوکس دارای دسترسی مدیریت شبکه دارد؛ این دسترسی در محیط توسعه موجود نبود.

## تغییر IP عمومی سرور ایران

پس از فعال شدن آدرس جدید روی همان سرور، در منوی «ساخت و مدیریت تونل‌ها» گزینه **۶: تغییر IP سرور ایران (همه تونل‌ها)** را انتخاب کنید. این گزینه IP کارت شبکه را تغییر نمی‌دهد.

آدرس جدید در اطلاعات همه تونل‌ها و سرویس‌های دائمی GRE ثبت می‌شود؛ پورت‌ها، توکن‌ها، MTU و شمارنده‌های ترافیک حفظ می‌شوند. تنظیمات قبلی در مسیر پشتیبان ذخیره می‌شوند و در صورت شکست اعمال تغییر، بازیابی آن‌ها انجام می‌شود. در سرورهای پشت NAT، آدرس محلی GRE از مسیر شبکه گرفته می‌شود و آدرس عمومی جدید در کد اتصال قرار می‌گیرد.

برای وصل شدن مجدد، فرمان اتصال جدیدی که برای هر تونل نمایش داده می‌شود را روی سرور خارج همان تونل اجرا کنید. فرمان‌ها گزینه `--force` دارند تا اتصال قبلی را جایگزین کنند؛ تا انجام این مرحله اتصال تونل‌ها قطع خواهد بود. این عملیات برای تغییر آدرس همان سرور است؛ انتقال به یک سرور ایران تازه به انتقال تنظیمات هم نیاز دارد.

فرمان مستقیم روی ایران:

```bash
NavaTunnel iran-ip --ip NEW_IRAN_IP
```

پس از استفاده از فرمان مستقیم، کد جدید هر تونل را از گزینه «دریافت کد اتصال خارج» بگیرید و با `--force` روی سرور خارج اعمال کنید.

## انتخاب و تغییر پورت کنترل FRP

هنگام ساخت تونل روی ایران، پورت کنترل را وارد کنید یا Enter / `auto` بزنید تا پورت آزاد انتخاب شود؛ `0` ساخت را لغو می‌کند. پورت TCP کنترل، پورت UDP همان شماره برای KCP و پورت UDP همراه QUIC از نظر تداخل با تونل‌ها، پورت‌های سرویس و پورت‌های فعال سیستم بررسی می‌شوند. QUIC از پورت بعدی استفاده می‌کند؛ برای پورت کنترل 65535، پورت QUIC برابر 65534 است.

برای تونل موجود، **مدیریت همان تونل → ۱۲) تغییر پورت کنترل FRP** را انتخاب کنید. شماره جدید را وارد کنید یا `auto` بنویسید؛ Enter و `0` یعنی لغو. فقط تنظیمات و سرویس FRPS همان تونل تغییر می‌کنند؛ پورت‌های سرویس، توکن، GRE، MTU و مصرف ترافیک حفظ می‌شوند. اگر اعمال تغییر شکست بخورد، تنظیمات قبلی بازیابی می‌شوند.

اتصال خارج تا اجرای کد جدید قطع خواهد بود. فرمان آماده با `--force` نمایش داده می‌شود؛ آن را روی سرور خارج همین تونل اجرا کنید. UFW فعال برای پورت‌های جدید تنظیم می‌شود؛ فایروال سفارشی و فایروال دیتاسنتر را جداگانه هماهنگ کنید.

```bash
NavaTunnel peer-control-port --id 2 --port 45000
# یا انتخاب خودکار:
NavaTunnel peer-control-port --id 2 --port auto
```

## توقف و شروع تونل

در مدیریت تونل روی ایران، **۱۳) توقف همین تونل** و **۱۴) شروع همین تونل** را انتخاب کنید. روی خارج، گزینه‌های **۶) توقف** و **۷) شروع** در مدیریت اتصال قرار دارند. توقف، FRP و سرویس ترافیک پوششی همان تونل (اگر موجود باشد) را متوقف می‌کند و سپس GRE همان تونل را پایین می‌آورد. شروع به ترتیب GRE و FRP را راه‌اندازی می‌کند و سرویس پوششی را فقط اگر پیش از توقف فعال بوده باشد، برمی‌گرداند.

تنظیمات، توکن، پورت‌ها، MTU، شمارنده‌ها و سقف ترافیک حفظ می‌شوند؛ سرویس شمارنده مشترک متوقف نمی‌شود. توقف دستی در `/etc/gre-panel/stopped/` ثبت و با شرط systemd روی سرویس‌ها اعمال می‌شود؛ ریبوت و ری‌استارت خودکار آن را لغو نمی‌کنند. برای بازگشت به کار، گزینه شروع را اجرا کنید. شروع ناموفق، سرویس‌های نیمه‌راه‌اندازی‌شده را متوقف می‌کند. فعال‌شدن سرویس محلی به‌تنهایی اتصال سمت مقابل را تأیید نمی‌کند.

```bash
# روی ایران؛ شناسه واقعی تونل:
NavaTunnel tunnel-power stop --id 2
NavaTunnel tunnel-power start --id 2
# روی خارج:
NavaTunnel tunnel-power stop --foreign
NavaTunnel tunnel-power start --foreign
```
